Most of my best documentation work is protected by NDAs, so how do I show what I can do? I built a site of my own.

<!-- truncate -->

## Why I built this site

I built this site to showcase my technical writing and to demonstrate the tools and AI-assisted workflows behind it.

I wanted the portfolio to feel like a small help portal, with clear navigation, a table of contents, and search. Docusaurus also let me show a docs-as-code workflow, including automated checks on every pull request.

This blog is the next step. I'll use it to share what I learn and to document how the site evolves.

## What I've added so far

Since the first version, I've worked on the site's look, its content, and the workflows that keep it healthy.

- **Visual design** — Customized the CSS to create a minimalist look and make pages easier to scan. Design is subjective, so I'll keep refining it.
- **Navigation** — Adjusted sidebar typography and spacing, and used expandable sections to help keep longer documentation manageable.
- **Icons** — Experimented with Napkin AI and added minimalist icons to the Welcome page.
- **API reference** — Integrated an OpenAPI plugin to render endpoint documentation from an API specification.
- **Page metadata** — Added YAML front matter to pages as I work toward more consistent titles, descriptions, and organization.
- **Content checks** — Added Vale for prose checks and Lychee for link checking.
- **AI-assisted workflows** — Started adding skills to automate repeatable tasks. For example, `/peek` starts a local site preview.
- **Search and changelog** — Added site search and a changelog to make content easier to find and site updates easier to follow.
